<Panel heading="How server errors become client exceptions">

When the server returns an error response, the client builds the exception as follows:

* **Status code 409 (Conflict)**:
  * If the error type is `DocumentConflictException`, a `DocumentConflictException` is created.
  * If the error type is `ClusterTransactionConcurrencyException`,
    a `ClusterTransactionConcurrencyException` is created, with the violations listed in the response.
  * Otherwise a `ConcurrencyException` is created.

* **Any other status code**: the client resolves the exception type from the error type name sent by the server.
  * If the type cannot be resolved or created, a `RavenException` is thrown.
  * If the resolved type is not a `RavenException`, it is wrapped in a `RavenException`
    when the command's unsuccessful-response behavior is `WrapException`.

* **A malformed error body**: if the response cannot be parsed into the error schema,
  an `InvalidOperationException` is thrown.
  If the parsed error has a null `Message`, `Error` or `Type`, a `BadResponseException` is thrown.

</Panel>

<Panel heading="Concurrency exceptions">

| Exception                              | Derives from                | Thrown when                                                                                         |
|----------------------------------------|-----------------------------|-----------------------------------------------------------------------------------------------------|
| `ConflictException` (abstract)         | `RavenException`            | Base class of the conflict exceptions below. It is not thrown directly.                              |
| `ConcurrencyException`                 | `ConflictException`         | The server answers with status 409 and the error type is neither `DocumentConflictException` nor `ClusterTransactionConcurrencyException`. |
| `ClusterTransactionConcurrencyException` | `ConcurrencyException`    | A cluster-wide transaction fails because of concurrency violations. The server sets status 409 and attaches the violations. |

`ConcurrencyException` has these properties:

| Property               | Type     | Description                |
|------------------------|----------|----------------------------|
| `Id`                   | `string` | The document ID            |
| `ExpectedChangeVector` | `string` | The expected change vector |
| `ActualChangeVector`   | `string` | The actual change vector   |

`ClusterTransactionConcurrencyException` adds `ConcurrencyViolations`, an array of `ConcurrencyViolation`:

| Property   | Type              | Description                                                                |
|------------|-------------------|----------------------------------------------------------------------------|
| `Type`     | `ViolationOnType` | `Document` or `CompareExchange`: where the concurrency check failed        |
| `Id`       | `string`          | The ID on which the check failed                                           |
| `Expected` | `long`            | The expected index                                                         |
| `Actual`   | `long`            | The actual index                                                           |

Since `ClusterTransactionConcurrencyException` derives from `ConcurrencyException`,
catch it first:

<CodeBlock language="csharp">
{`try
\{
    session.SaveChanges();
\}
catch (ClusterTransactionConcurrencyException e)
\{
    foreach (ClusterTransactionConcurrencyException.ConcurrencyViolation violation in e.ConcurrencyViolations)
    \{
        // violation.Type, violation.Id, violation.Expected, violation.Actual
    \}
\}
catch (ConcurrencyException e)
\{
    // e.Id, e.ExpectedChangeVector, e.ActualChangeVector
\}
`}
</CodeBlock>

</Panel>

<Panel heading="Wait-after-save timeouts">

`RavenTimeoutException` (derives from `RavenException`) has the public field `FailImmediately` (`bool`).
The server throws it, with `FailImmediately` set to `true`, in two cases while processing `SaveChanges`:

* After `session.Advanced.WaitForReplicationAfterSaveChanges` was called with `throwOnTimeout` set to `true`,
  and the change vector was replicated to fewer servers than requested within the timeout.
* After `session.Advanced.WaitForIndexesAfterSaveChanges` was called with `throwOnTimeout` set to `true`,
  and the indexes did not catch up within the timeout.
  The message lists the stale, errored and paused indexes.

With `throwOnTimeout` set to `false`, the server does not throw in these cases.

</Panel>

<Panel heading="Backup already running">

`BackupAlreadyRunningException` (namespace `Raven.Client.Exceptions.Database`, derives from `RavenException`)
is thrown by the server when a backup task is started while a backup of the same task is already running.
It has two public fields, which the client fills from the error response:

| Field         | Type     | Description                                      |
|---------------|----------|--------------------------------------------------|
| `OperationId` | `long`   | The ID of the backup operation that is running   |
| `NodeTag`     | `string` | The tag of the node on which the backup is running |

</Panel>

<Panel heading="Request executor exceptions">

`AllTopologyNodesDownException` derives from `Exception` (not from `RavenException`).
Its property `FailedTopology` (`Topology`) holds the topology that was used, when it is known.

It is thrown:

* By the request executor when a request failed on every node of the topology and more than one node failed.
  The message lists each node's URL, cluster tag, server role and exception.
  When exactly one node failed, the exception of that node is rethrown instead.
* By the node selector when the topology has no nodes at all, while it selects a node by session ID.

`BadResponseException` (derives from `RavenException`) is thrown while an error response is converted
to an exception, when the parsed error is null or has a null `Message`, `Error` or `Type`.

</Panel>

<Panel heading="Index, sorter and collection exceptions">

All of these derive from `RavenException`.

| Exception                         | Thrown when |
|-----------------------------------|-------------|
| `IndexDoesNotExistException`      | The query result is null, so the client throws "Could not find index ...". The server also throws it for a missing index ("There is no index with '...' name.") or a missing auto index ("There is no auto index with '...' name."). |
| `IndexAlreadyExistException`      | An index is edited while its lock mode is `IndexLockMode.LockedError`. The message is "Cannot edit existing index ... with lock mode ...". |
| `IndexCreationException`          | The server cannot create an index, for example: a JavaScript index definition has a problem, the index configuration contains an unrecognized option key, or a license limit blocks the creation (the `LicenseLimitException` is the inner exception). |
| `IndexDeletionException`          | The server fails to delete or reset an index. The original exception is the inner exception. |
| `IndexInvalidException`           | The server finds an invalid index definition detail, for example an unsupported or duplicated-field pattern in the references pattern of a map-reduce output to a collection. |
| `PendingRollingIndexException`    | A query uses an index on a node where a rolling index deployment is still pending. |
| `NotImplementedInCoraxException`  | A Corax index uses a feature that Corax does not implement, such as indexing-time boosting of a field in a document, or stream values. |
| `SorterDoesNotExistException`     | A query names a custom sorter that the server cannot find ("There is no sorter with '...' name."). |
| `DocumentCollectionMismatchException` | An update would change the collection of a document. The message says to delete the document and recreate it. |

</Panel>

<Panel heading="Database state exceptions">

All of these derive from `RavenException`.

| Exception                                | Thrown when |
|------------------------------------------|-------------|
| `DatabaseDisabledException`              | The database is disabled: a `disable.marker` file exists in its data directory, or the (sharded) database record is disabled. A subscription worker also throws it when the server reports the database as disabled. |
| `DatabaseLoadFailureException`           | The database fails to start. The message contains the database name and its data directory, and the cause is the inner exception. |
| `DatabaseSchemaErrorException`           | The database fails to start because of a storage schema error. Same message format as above. |
| `DatabaseLoadTimeoutException`           | Loading a database for a TCP connection, or unloading a database for a request, times out. |
| `DatabaseConcurrentLoadTimeoutException` | Too many databases are loading concurrently and the wait for a free slot times out. |
| `DatabaseIdleException`                  | A replication attempt without changes reaches an idle database, or the remote task topology of a pull-replication sink is requested for an idle database. |
| `DatabaseNotRelevantException`           | A cluster transaction reaches a node that is only a promotable member of the database group, or a sharded database's orchestrator is requested on a node where it is not relevant. |
| `DatabaseRestoringException`             | The database state is `RestoreInProgress` when its configuration is created. |
| `ServerLoadFailureException`             | The server fails to load its system storage. |

</Panel>

<Panel heading="Cluster and node exceptions">

| Exception                           | Derives from       | Thrown when |
|-------------------------------------|--------------------|-------------|
| `NoLeaderException`                 | `RavenException`   | A node that is not the leader receives a command that only the leader accepts, or the node loses leadership while it handles one. |
| `NodeIsPassiveException`            | `RavenException`   | An action on a database, or a request for TCP info, reaches a node that is passive. |
| `RequestedNodeUnavailableException` | `Exception`        | The request executor was asked for a specific node and either the node tag is not in the topology, or the node is currently marked as unavailable (when the caller asked to throw on failures). |
| `InvalidNetworkTopologyException`   | `Exception`        | A TCP connection attempt (for example from replication) is answered with the `InvalidNetworkTopology` status. |
| `UnsuccessfulRequestException`      | `Exception`        | The request executor records it per failed node: it is the inner exception of `AllTopologyNodesDownException`, and it is stored for a node when a request is no longer relevant for that node. |
| `ClientVersionMismatchException`    | `RavenException`   | The server rejects a client of major version 3, or a client with a newer build version than the server. |
| `RouteNotFoundException`            | `RavenException`   | The server has no handler for the requested HTTP method and path. |

</Panel>

<Panel heading="Attachment, counter, revisions and license exceptions">

All of these derive from `RavenException`.

| Exception                         | Thrown when |
|-----------------------------------|-------------|
| `AttachmentDoesNotExistException` | An attachment name is not found for a document ("There is no attachment with '...' name for document '...'."), or the metadata of a non-existing remote attachment is updated. |
| `InvalidAttachmentRangeException` | The server answers a get-attachment request with status 416 (Requested Range Not Satisfiable). The message contains the range, the attachment name and the document ID. |
| `CounterOverflowException`        | Incrementing a counter overflows a `long`, or the sum of a counter's per-node values overflows when it is read and the value is not capped on overflow. |
| `RevisionsDisabledException`      | Revisions are deleted before a given time while no revisions configuration exists on the database. |
| `LicenseActivationException`      | A license activation or update fails and the caller asked to throw on failure. The original exception is the inner exception. |

</Panel>
