<Admonition type="note" title="">

* **When deploying an index**:  
  * If the new index definition is **different** from the current index definition on the server,  
    the current index will be overwritten and data will be re-indexed according to the new index definition.
  * If the new index definition is the **same** as the one currently deployed on the server,  
    it will not be overwritten and re-indexing will not occur upon deploying the index.

* **Prior to deploying an index:**,  
  * Use `IndexHasChangedOperation` to check if the new index definition differs from the one  
    on the server to avoid any unwanted changes to the existing indexed data.  

* In this page:

## Check if index has changed


<Tabs groupId='languageSyntax'>
<TabItem value="Sync" label="Sync">
<CodeBlock language="csharp">
{`// Some index definition
var indexDefinition = new IndexDefinition
{
    Name = "UsersByName",
    Maps = { "from user in docs.Users select new { user.Name }"}
};

// Define the has-changed operation, pass the index definition
var indexHasChangedOp = new IndexHasChangedOperation(indexDefinition);

// Execute the operation by passing it to Maintenance.Send
bool indexHasChanged = store.Maintenance.Send(indexHasChangedOp);

// Return values:
// false: The definition of the index passed is the SAME as the one deployed on the server  
// true:  The definition of the index passed is DIFFERENT than the one deployed on the server
//        Or - index does not exist
`}
</CodeBlock>

## Compare index definitions on the client

`IndexHasChangedOperation` compares the definition on the server.  
To compare two `IndexDefinition` objects that you already hold, use `IndexDefinition.Compare`.

<TabItem value="compare_definitions" label="compare_definitions">
<CodeBlock language="csharp">
{`var localDefinition = new IndexDefinition
{
    Name = "UsersByName",
    Maps = { "from user in docs.Users select new { user.Name }" }
};

var deployedDefinition = store.Maintenance.Send(new GetIndexOperation("UsersByName"));

if (deployedDefinition != null)
{
    IndexDefinitionCompareDifferences differences = localDefinition.Compare(deployedDefinition);

    if (differences.HasFlag(IndexDefinitionCompareDifferences.Maps))
    {
        // The map functions are different
    }
}
`}
</CodeBlock>
</TabItem>

<TabItem value="compare_syntax" label="syntax">
<CodeBlock language="csharp">
{`public IndexDefinitionCompareDifferences Compare(IndexDefinition other)
`}
</CodeBlock>
</TabItem>

* `Compare` throws an `ArgumentNullException` when `other` is `null`.  
  It returns `IndexDefinitionCompareDifferences.None` when `other` is the same object, or when no difference is found.

* `IndexDefinition.Equals(IndexDefinition)` is `true` when `Compare` returns `None`,  
  or when the differences contain none of `Maps`, `Reduce`, `Configuration` and `Fields`.

#### `IndexDefinitionCompareDifferences`

The result is a `[Flags]` enum. The values that `Compare` sets:

| Value | Set when |
| - | - |
| `None` | No difference was found |
| `Maps` | The sets of map functions differ. Line endings are normalized before they are compared. |
| `Reduce` | The reduce functions differ (line endings are normalized), or `OutputReduceToCollection`, `PatternForOutputReduceToCollectionReferences` or `PatternReferencesCollectionName` differ (case-insensitive comparison). |
| `Fields` | The `Fields` dictionaries differ |
| `Configuration` | The `Configuration` dictionaries differ |
| `LockMode` | The lock modes differ. `null` and `Unlock` are treated as equal. |
| `Priority` | The priorities differ. `null` and `Normal` are treated as equal. |
| `State` | The states differ. `null` and `Normal` are treated as equal. |
| `AdditionalSources` | The additional sources differ. Line endings are normalized. |
| `AdditionalAssemblies` | The sets of additional assemblies differ |
| `DeploymentMode` | The deployment modes differ. Not set when `other.DeploymentMode` is `null`. |
| `CompoundFields` | The compound fields differ |
| `ArchivedDataProcessingBehavior` | The archived data processing behaviors differ |
| `SchemaValidationConfiguration` | The `SchemaDefinitions` differ |
| `All` | The combination of all the values above, except `None` |

#### `GetIndexHash`

<TabItem value="get_index_hash_syntax" label="syntax">
<CodeBlock language="csharp">
{`public byte[] GetIndexHash()
`}
</CodeBlock>
</TabItem>

* `GetIndexHash` returns the bytes of the definition's `GetHashCode()`, which is computed from the maps,  
  the reduce function, the fields, the additional sources, the additional assemblies and `OutputReduceToCollection`.

* The result is cached in the `IndexDefinition` object on the first call.  
  Changing the definition afterwards does not change what later calls return.


## Syntax

<TabItem value="syntax" label="syntax">
<CodeBlock language="csharp">
{`public IndexHasChangedOperation(IndexDefinition definition)
`}
</CodeBlock>
</TabItem>

| Parameters | Type | Description |
| - | - | - |
| **definition** | [IndexDefinition](../../../../../client-api/operations/maintenance/indexes/put-indexes.mdx#indexdefinition) | The index definition to check |

| Return Value | Description |
| - | - |
| `true` | When the index **does not exist** on the server<br/>or -<br/>When the index definition **is different** from the one deployed on the server  |
| `false` | When the index definition is **the same** as the one deployed on the server |
